# コミュニケーションのルール

- 日本語で答える。専門用語（FVF、Net、損益分岐など）は初出で短く言い換える。用語は `knowledge/用語集.md`。
- ユーザーは副業1年未満。「どのファイルをどこに置くか」などの手作業はできるだけ Claude が直接行い、ユーザーに頼む作業は**コピペ1回で済む形**にする。
- 言われなくても使いやすさ・効率の改善を実施・提案する（例: リンクは関連する数字や名前に付ける、長い表示は短く、よく使う操作は1クリックに）。
- 結果は「何をしたか → 分かったこと → 次にやること」の順で、表を使って短く。
- **推測で進めない。確認が必要なことは、作業の前に質問する**（ユーザーの指示）。選択肢を示して聞き、答えを待ってから実装する。
- データが無いときは「無い」と書き、どう取れば埋まるかを示す。
- 金額の表示は「何の金額か（入札欄に入れる額／支払う額／税込・税抜）」が一目で分かる言葉にする。
- **自動化できるものは確認なしで自動化して進める**（2026-11-17 ユーザー指示）。利益・お金・顧客（購入者）に関わる判断、元に戻せない操作はユーザーに確認する。
- ユーザーの手作業は「プルリクのマージ」と「ターミナルでのコマンド1回」までにする。コピペ・画面操作が要る仕組みは避け、どうしても必要なときは作業の前に回数を伝える。
- クラウドから Mac に届けたいものは、古物台帳（元の台帳。2026-11-17 から1冊運用）のシートに書いて `ledger_sync.py` が毎朝取り込む形にする（新しいシートは「共有_〜」の名前にすれば Apps Script の貼り替えが要らない）。
- **手順で開くページには必ず URL（リンク）を付ける**（2026-11-20 ユーザー指摘「URL を都度貼って」）。「〇〇の画面で」だけで終わらせない。プログラムが案内するときは、そのページをブラウザで自動で開く。
- **ユーザーに頼む作業は、毎回そのメッセージだけで完結させる**（2026-11-20 ユーザー指摘「前のメッセージをいちいち確認しに行けということね」）。「前のメッセージの手順」「上の」「さっきの」で済ませず、URL・コマンド・押すボタン・順番をその場で全部書き直す。長くなっても繰り返す。
- **指摘は1件の直しで終わらせず、原則にして全部に当てはめる**（同日「全てにおいて」）。指摘を受けたら ①何が根っこか（例: ユーザーの手間を増やした）を言葉にし、②このファイルか該当のルールに書き、③同じ根っこのほかの場面（報告・プログラムの案内・担当者への依頼文）も同時に直す。根っこはだいたい「ユーザーの手間・探す・覚えておくを増やした」か「確かめずに言った」のどちらか。
