# 情報管理のルール（最重要）

- GitHub リポジトリ `aurora-project` は**公開**。
- 次は**絶対にコミットしない**: `data/`（仕入値・販売実績）、`knowledge/`（事業ナレッジ・目標・実績）、`reports/`（レポート）、`extension/`（相場データ入りの拡張機能）。いずれも .gitignore 済み。
- **例外（2026-11-15 ユーザー承認）**: 店舗アプリ用の相場データ（store_data.json）だけは、`tools/store_publish.py` で
  **合言葉で暗号化（AES-256-GCM）したもの**を GitHub の**シークレット Gist**（公開リポジトリではない）に置いてよい。
  合言葉・GitHub のトークンは Mac のキーチェーンだけに保存し、リポジトリ・チャット・ファイルには書かない。暗号化していない data/ は置かない。
- API トークン・合言葉（Chatwork・Apps Script の古物台帳 URL・eBay・GitHub）はすべて Mac のキーチェーン（`tools/keychain.py`）。
- **店舗アプリ用の鍵（2026-11-20 ユーザー決定）**: 古物台帳の「共有_店舗」に行を足すことしかできない別の鍵（読む・消す・ほかのシートは不可。`ledger_sync.py` の `storeAdd`）。キーチェーンで作り、Apps Script の URL と一緒に store_data.json に入れて iPhone に届ける（Gist へは暗号化して。iCloud Drive の写しはユーザー本人の場所）。リポジトリ・チャットには書かない。漏れたら `python3 tools/ledger_sync.py script` の前にキーチェーンの store_key を消せば新しい鍵になる。
- `.claude/` と CLAUDE.md は公開される。ここには氏名・取引先の個人名・金額の実績・口座・スプレッドシートIDなどを書かない（事業の中身は knowledge/ に書く）。
- コミット前に `git status` と `git diff --cached` で、上記が含まれていないか確認する。
- 外部サービス（Web検索など）に個人名・取引情報を送らない。

## 規約の順守
- **eBay のページ（検索結果・販売履歴・出品）をプログラムで自動取得しない。** スクレイピングは eBay の規約違反。 eBay の相場は、ユーザーが sold リンクや Product Research で確認した数字、自分の販売実績、Chatwork・頒布会のデータだけを使う。
- 他のサイトでも、自動取得の前に利用規約で許されているか確認し、分からなければユーザーに確認する。
- **ヤフオクは robots.txt の Allow の形だけ読む**（2026-11-19 ユーザー決定）。読む前に `tools/robots.py` で URL を検査し、Disallow の引数（`/search/`・`/seller/` の n=・s1=・o1=・mode=・select= など、`/closedsearch/` の n=・aucminprice= など）は外す。外しても Disallow の URL は読まずに警告する。間隔は1.5秒以上、1回に読むページ数に上限（config.toml [yahoo_search]・[win_score]）。並べ替えは読んだ後に Mac・拡張機能の中で。ユーザーが開いているページそのものは対象外（拡張機能が続きのページを読むときは外す）。
- 仕入れ先の規約（2026-11-19 確認）: **メルカリ・ラクマは事業者の利用を規約で禁止**しているので、仕入れに使わず、向けの仕組み（拡張機能など）も作らない。ヤフオク・Yahoo!フリマは購入側に事業者の制限なし。カメラのキタムラは禁止なし（転売目的は初期不良交換なし）。新しい仕入れ先は、仕組みを作る前に規約で「事業者が買えるか」「ページを読む仕組みが許されるか」を確かめる（詳細は knowledge の「仕入れ先の規約」）。
- **出品の説明文は事実どおりに書く。** 分かっている不具合（AF不良・カビ・クモリなど）を「未確認」と書くなど、事実と違う説明は作らない（民法572条: 知りながら告げなかった不具合はノークレームノーリターンでも免責されない）。書き方を控えめにするのはよいが、うそは書かない。
- 法令（古物営業法・民法・特定商取引法など）やヤフオク・eBay の規約に反する依頼は、理由を短く伝えて断り、守れる代わりの案を出す。
