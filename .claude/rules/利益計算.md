# 利益計算のルール

- **保守的に**計算する。迷ったら安い相場・高いコストを採る。赤字仕入れを防ぐことが最優先。
- 入札判断の基準: 利益2,000円以上 **かつ** 利益率（売上＝eBay売値の円換算に対する割合）8%以上で**全体統一**（2026-11-17 ユーザー決定。落札を増やすため 2,500円・10% から下げた。安心ストアなどの例外なし。損益分岐を超える入札はしない。`tools/config.toml` の [judge]）。
- ジャンク表記は気にしない（届くまで分からないため）。割り引かず、ジャンクという理由だけでは要確認にしない。
- eBay 出品中の最安値から相場を出すとき: **送料無料の出品は出品額 − $30**、送料を別に取っている出品は出品額（商品代）そのままを、送料別の商品代として提示する。sold（売れた価格）も同じく、送料無料で売れたものは売れた額 − $30（2026-11-16 ユーザー決定。`active_free_ship_deduction_usd`。仮の相場は最安値）。
- 送料は販売価格から一律 $40 を差し引く（入札判断。2026-11-15 に $30 から変更。今から仕入れる商品は次の出品から送料 $40 を乗せるため）。出品中・販売済みの商品の見積もり（数字のグラフ）は $30（`listed_deduction_usd`）。eBay手数料: FVF実効12%＋海外1.55%＋広告2.2%＋$0.44。円転ロス2%。消費税還付は含めない。
- eBay の$は**送料を除いた商品代（net・送料別）**で表示・入力する（2026-11-15 ユーザー指定。拡張機能・スマホのアプリ・毎朝のレポート）。相場データ（price_memo.csv など）と計算は送料込みのまま持ち、入力された net には送料 $40 を足して保存する。
- ジャンク表記も想定販売価格は割り引かない（2026-11-16 ユーザー指定で7割評価をやめた。`junk_price_factor = 1.0`）。説明文や商品名にはっきり書かれた光学難（カビ・クモリ・バルサム等）は × で見送る（修理しない方針。2026-11-18 ユーザー決定・おまかせ: 実績は光学難ありの平均利益が赤字。「カビ・クモリなし」のような打ち消しは除く。傷・ヤケは要確認のまま）。
- 根拠の強さを必ず示す: 自分の販売実績 ＞ Chatwork実績 ＞ 頒布会リスト ＞ 鑑定表(推定)。**販売履歴は自分の古物台帳に限らず、Chatwork の他の人の事例と頒布会も含める（頒布会も売れたものとみなす。2026-11-18 ユーザー決定）**。この3つが根拠なら「確認不要」（`SURE_TIER = 2`）、鑑定表・仮の相場は「確認してから」。
- 数値を変えたら `config.toml` を直し、`knowledge/意思決定ログ.md` に日付付きで記録する。クラウドからは古物台帳（元の台帳。2026-11-17 から1冊運用）の「意思決定ログ」シート（日付・決めたこと）に書けば、毎朝の `update_all.py` が Mac の md に追記する。
- 入札候補の並び（2026-11-18 ユーザー決定）: 売れ筋（販売履歴＝自分・Chatwork・頒布会のある機種。仕入値が分かる記録は、その仕入値から見て基準以上の利益が出ていたものだけ）と売値（送料込み）$99超を上に、$99以下は下に回す。同じ順位の中は終了が近い順。判定・上限額は変えない（appraise.py の `bid_priority`・`sold_hit`、拡張機能の `bidPrio`）。
- 状態の補正（2026-11-18 ユーザー決定・おまかせ）: 1ランク $10 の固定額をやめ、価格に対する割合にした。自分・Chatwork の販売実績で、同じ機種の状態違いの組から1ランクあたりの%を毎回推定する（3〜15%。組が5つ未満なら `condition_step_pct` = 8%）。美品は上限が上がり、並品は下がる。
- 売れ筋の機種の検索（2026-11-18 ユーザー決定）: 毎朝の入札リストに、売れ筋の機種を名指しで探す検索を利益の大きい順に30本足す（メーカー＋型の語。1本100件。`appraise.py --hit-searches 30`、`hit_search_urls`）。販売履歴のある機種を入札リストに多く出すため。
- 負けた機種・古い相場（2026-11-18 ユーザー決定）: 直近60日に競り負けた機種も、売れ筋と同じく名指しで毎朝探す（最大20本。`lost_models`）。90日以上直していない相場メモは、毎朝「Mac_未登録機種」に最大10件足し、夜の下調べで見直す（`stale_memos`）。登録は朝に選ぶだけ。
- Chatwork の販売価格（2026-11-18 ユーザー決定）: スクールの方針でだいたい送料 $30 込み。商品代（送料別）＝報告額 − $30 とし、うちは送料 $40 で出品するので、計算上の売値（送料込み）＝商品代 ＋ $40（`chatwork_included_usd`、`appraise.chatwork_gross`）。例: 報告 $169 → 商品代 $139。
- まとめ売り（2026-11-18 ユーザー決定）: セット出品は、区切り（＋ + 、 , ／ / ＆ & 「と」）で分けた中身ごとに相場を当てて合計する。型の語（焦点距離・型番）がある部分だけを中身とし、相場が見つかった中身だけを足す（見つからない中身は $0）。2点以上見つかったときだけ判定し、2点目からは送料（一律）・1注文の手数料・梱包を引く（別々に売る前提）。中身が分からないセットは今までどおり要確認（`set_part_titles`・`set_value` / 拡張機能 `setPartTitles`・`setValue`）。
- F値とボディの型番（2026-11-18 ユーザー指摘）: 「F2」「F3」のような整数だけの語は、**すぐ前**が数字・焦点距離・レンズ名（Nikkor・Zuiko など）なら F値、それ以外（「Nikon F2」「ニコン F3 50mm」の F3）はボディの型番とみなす。f/2・f1.4・1:2 は常に F値（`is_f_number` / 拡張機能 `isFNumber`。商品名の書き方の一覧は `判定ロジック.md`）。
- 以前の入札分析ファイルのリサーチ（2026-11-19 ユーザー決定）: 「リサーチ貼付」の品名・eBay 売値$・講師価格を、古物台帳「共有_リサーチ相場」経由で相場に使う（`data/research_prices.csv`、根拠「リサーチ（推定）」= tier 3）。講師価格があれば講師価格。売れた額か送料込みか分からないので、送料無料とみなして −$30 を商品代とする。鑑定表と同じく「確認してから入札」で、自分・Chatwork・頒布会の記録がある機種はそちらを優先。販売履歴（売れ筋）には数えない。
